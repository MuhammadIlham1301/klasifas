# Implementation Backlog & Work Breakdown Structure (WBS)## KlasiFas — Klasifikasi Keluhan Fasilitas Kampus**Institusi:** FTII UHAMKA  **Kelompok:** 7  **Dokumen:** `docs/TASKS.md`  **Versi draf:** 0.2  **Status:** Draft — Menunggu Review Kelompok---## 1. Panduan Pelaksanaan dan Aturan Kerja### 1.1 Prinsip Kerja Inkremental1. Pengerjaan dilakukan secara bertahap, satu tugas utama dalam satu sesi kerja OpenCode.2. Sebelum implementasi, AI Coding Agent wajib membaca `AGENTS.md` dan dokumen acuan yang relevan.3. Implementasi hanya dilakukan pada tugas yang sudah memiliki ruang lingkup dan acceptance criteria yang jelas.4. Satu tugas harus selesai, diuji, dan diverifikasi sebelum beralih ke tugas berikutnya.5. OpenCode tidak boleh mengubah kebutuhan atau keputusan yang sudah ditetapkan dalam PRD, TECHSTACK, SECURITY, dan DESIGN tanpa persetujuan kelompok.6. Keputusan yang masih berstatus TBD tidak boleh ditetapkan sepihak oleh AI Coding Agent.7. Perubahan kode tidak boleh mengubah dokumen sumber secara otomatis. Pembaruan checklist TASKS dilakukan setelah hasil pekerjaan diverifikasi.### 1.2 Definition of Ready (DoR)Sebuah tugas dapat mulai dikerjakan apabila:- [ ] ID dan nama tugas sudah jelas.- [ ] Ruang lingkup dan kebutuhan terkait sudah disebutkan.- [ ] Dependensi tugas telah diselesaikan atau tersedia.- [ ] Acceptance criteria dapat diuji secara objektif.- [ ] Tidak terdapat keputusan TBD yang menghalangi implementasi.- [ ] Dokumen acuan telah dibaca oleh AI Coding Agent.Jika keputusan TBD memengaruhi implementasi, pekerjaan terkait harus menunggu keputusan kelompok atau dibatasi pada bagian yang tidak bergantung pada keputusan tersebut.### 1.3 Definition of Done (DoD)Sebuah tugas dapat ditandai selesai apabila:- [ ] Implementasi sesuai ruang lingkup dan acceptance criteria.- [ ] Tidak melanggar ketentuan keamanan dan arsitektur.- [ ] Pengujian unit atau integrasi yang relevan sudah tersedia dan lulus.- [ ] Tidak terdapat kredensial, secret, atau data mentah PII yang di-hardcode ke repositori.- [ ] Tidak menimbulkan regresi pada fitur yang sudah diverifikasi.- [ ] Hasil perubahan dapat diperiksa melalui kode, pengujian, atau demonstrasi.- [ ] Status tugas diperbarui setelah verifikasi.### 1.4 Protokol Pengujian- Pengujian otomatis menggunakan `pytest`.- Database pengujian menggunakan PostgreSQL khusus, yaitu `klasifas_test_db`, sesuai konfigurasi pengujian.- Untuk validasi terisolasi, database pengujian sementara baru dapat dibuat dari migrasi. Database sementara harus terpisah dari database development/operasional dan tidak menggantikan `klasifas_test_db`.- Seluruh test case yang telah didefinisikan wajib lulus: **100% test pass rate, 0 failures, dan 0 errors**.- Angka tersebut bukan target code coverage 100%.- Pengujian autentikasi, otorisasi, validasi input, transisi status, token, fallback ML, dan audit log harus mencakup skenario berhasil maupun ditolak.- Pengujian yang bergantung pada keputusan TBD harus ditandai sebagai tertunda, bukan dianggap lulus.---## 2.
